# DFA INTERSECT outcomes

- **Polished mobile-first application shell:** The app presents an attractive responsive shell with a clear brand/header, compact mobile actions, a primary experiment card, a touch-friendly feature menu, and adaptive layouts for phone-sized screens and desktop.
- **Branded splash screen:** On launch, DFA INTERSECT shows a centered node-logo splash with the app name, automata-lab descriptor, loading indicator, and a reduced-motion fallback before revealing the workspace.
- **Grouped feature menu:** The app uses one clear menu bar to separate Explore features (Simulator, Transition table, Batch tests) from Build & learn features (DFA editor, Theory guide), with only the selected workspace rendered in the main canvas.
- **Complete reusable DFA language library:** DFA INTERSECT exposes a generated library of individual binary and decimal DFAs covering starts/ends with, prefixes/suffixes, substrings and complements, parity/counting, length modulo, divisibility, decimal last-digit rules, modulo residues, and finite palindrome examples. Every library DFA has complete deterministic transitions, explicit examples/non-examples, and ε behavior.
- **Independent searchable M₁/M₂ selectors:** Users can choose any supported DFA independently for Language 1 (M₁) and Language 2 (M₂) through searchable, category-filtered selectors with Binary/Decimal/All alphabet filters, compact DFA information cards, Random compatible pair, and Swap M₁ ↔ M₂ controls.
- **Safe product construction:** Selected DFAs flow into the existing Union, Intersection, Difference, and XOR product engine. Incompatible alphabets, missing transitions, invalid states, or invalid initial/final references block construction with a friendly warning instead of silently building an incorrect product.
- **DFA editing and validation remain usable:** Users can continue creating and modifying M₁ and M₂ states, alphabets, start and accepting states, and transitions through the existing editor with accessible controls and visible validation.
- **Interactive automata visualization remains usable:** The simulator keeps the three-machine visualization, active-state highlighting, drag interaction, and reachable-state filtering while fitting small screens through responsive stacking and horizontal overflow where needed.
- **Parallel simulation stays clear:** Users can enter or select input strings, play/pause/replay, step through execution, change playback speed, and see the resulting regular union behavior across M₁, M₂, and the product DFA.
- **Batch testing remains available:** Users can enter and review multiple strings with pass/fail results across the relevant automata and jump back to simulation for a selected string.
- **Product transition table remains responsive:** Users can inspect the product transition table, toggle reachable-only behavior, switch the operation mode, and read active-state highlighting in compact mobile presentation.
- **Theory guidance remains integrated:** Users can open the theory/viva workspace and read explanations of DFA concepts, regular union construction, and how the displayed product results are derived.
- **Export workflows remain intact:** Users can open export, choose LaTeX, JSON, CSV, or lab summary output, copy the generated content, and download the selected file.
- **Managed preview is routable and diagnosable:** The SPA serves `GET /manus-routes.json` with the root route and TypeScript diagnostics are registered for the project.
